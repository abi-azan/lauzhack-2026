# SBB Mobile look-alike: Kotlin Multiplatform + Compose Multiplatform

The passenger app. One Compose Multiplatform app for **Android** and the **web (wasmJs)**, pixel-matched to SBB Mobile
12.60 (measured on a Pixel 10a). Almost everything lives in `commonMain`. How it fits with the server:
[`docs/ARCHITECTURE.md`](../../docs/ARCHITECTURE.md). Testing on a real phone: [`TESTING.md`](TESTING.md).

## What it does

| Feature | Where |
|---|---|
| The SBB Mobile shell: Plan (timetable, connections, network map), Trips, EasyRide, Tickets, Shop, Profile | `screens/<area>/` |
| Check-in: passive Bluetooth beacon check-in after a one-time opt-in, the EasyRide swipe, or a QR code / deep link (`#/checkin/<trainId>?car=N`) | `incident/PassiveCheckIn.kt`, `screens/easyride/`, `androidMain/.../platform/BeaconScanner.android.kt` |
| Live updates over `/ws/passenger`; after a server reset or restart the app checks in again by itself | `incident/PassengerStore.kt` |
| One notification per incident, updated in place. Android: a foreground service keeps the WebSocket alive with the screen off. Web: the browser's Notification API. | `androidMain/.../platform/RideService.kt`, `AndroidNotifier.kt`, `wasmJsMain/.../PlatformServices.wasmJs.kt` |
| The incident sheet ("Information"): the official update, the next-move card (labelled "Estimate", with its sources), "Ask a question" | `screens/incident/IncidentScreen.kt`, `screens/easyride/NextMoveCard.kt` |
| The support chat, a sheet that answers only from published facts (server: `POST /api/chat/{token}`) | `screens/easyride/ChatSheet.kt`, `incident/chat/` |
| Offline scripted demo when no backend is reachable | `incident/Script.kt` |

**Which backend it talks to:**
- **Web:** the page's own origin (the demo server serves the app at `/`), or `?api=<url>` for one visit (`?api=off` runs the offline demo).
- **Android:** `http://localhost:8080` (with `adb reverse tcp:8080 tcp:8080`), `http://10.0.2.2:8080` on the emulator, or the address set with `adb shell am start -n railstatus.mobile/.MainActivity --es api https://<tunnel>` (remembered). More switches (fake beacon, persona, check in/out) are in [`TESTING.md`](TESTING.md) and `DemoConfig.kt`.

## Layout

```
native/
  composeApp/
    src/commonMain/kotlin/railstatus/mobile/
      App.kt          the whole app: SbbTheme { SbbApp() }
      AppGraph.kt     long-lived state; PlatformServices (expect/actual): HTTP, notifier, beacon scanner, storage
      ui/theme/       colours (light/dark), dimens, SBB fonts and type scale
      ui/chrome/      Header, Segmented(+Page), TabBar (+ measured motion), SbbSheet, SbbScreen/ScreenColumn, SbbLoader
      ui/components/  SbbText, SbbIcon, buttons, cards, list rows, badges, Landscape (illustrations), pressed state
      ui/map/         the route and network map
      nav/            Navigator (a back stack per tab), NavHost (push/back slide), deep links, SbbApp (the shell)
      screens/<area>/ one file per screen
      data/           timetable and stations
      incident/       check-in, live connection, notifications policy, chat store
    src/commonMain/composeResources/
      values*/strings*.xml  en, de, fr, it (the app follows the device language)
      font/, drawable/, files/map/   generated by the build, gitignored
    src/androidMain/  MainActivity (edge to edge, deep links), RailApp, manifest, platform/ (ride service,
                      notifier, Bluetooth scanner, permissions, storage, DemoConfig)
    src/wasmJsMain/   main() with ComposeViewport, PlatformServices, index.html
  assets/
    icons/*.svg         SBB icons (Apache-2.0); add an icon by dropping its SVG here
    illustrations/      official SBB scenes, *-light.webp / *-dark.webp
    map/                map data (OpenStreetMap via OpenFreeMap) and the scripts that build it
```

The tab bar's measured motion table is `ui/chrome/TabBarMotionData.kt` (from a 120 fps recording of the phone).

The backend's API types (`../kmp/shared/src/commonMain/kotlin`, package `railstatus.model`) are compiled in as an extra
`commonMain` source dir. Note `railstatus.mobile.data.Station/Stop` vs `railstatus.model.Station/Stop`: use import aliases.

## Build and run

Needs JDK 17+ and the Android SDK (`local.properties` with `sdk.dir=...`, or `ANDROID_HOME`).

```sh
./gradlew :composeApp:assembleDebug                       # APK: composeApp/build/outputs/apk/debug/
./gradlew :composeApp:installDebug                        # onto a device/emulator
./gradlew :composeApp:wasmJsBrowserDevelopmentRun         # web, dev server (default port 8080, the same as the backend's)
./gradlew :composeApp:wasmJsBrowserDistribution           # web, static files in composeApp/build/dist/wasmJs/productionExecutable
./gradlew :composeApp:testDebugUnitTest                   # common tests on the JVM
CHROME_BIN=$(which chromium) ./gradlew :composeApp:wasmJsBrowserTest   # the same tests in headless Chromium
adb shell am start -a android.intent.action.VIEW -d 'railstatus://checkin/<trainId>?car=7'   # deep link
```

The first build needs network: it downloads the SBB fonts. The web build scales the UI so the page is always
411.43 dp wide (the reference phone); it accepts `?theme=light|dark`, `?api=<url>` and `#/<tab>`.

Source assets live once in `native/assets/`; the build derives the rest (nothing generated is committed):

| What | From | To |
|---|---|---|
| SBB Web v1.9 fonts (not open source, never committed) | `https://cdn.app.sbb.ch/fonts/v1_9_subset/*.woff` | `composeResources/font/sbb_{thin,light,roman,bold}.ttf` (task `fetchSbbFonts`, WOFF to TTF in Gradle; cache in `composeApp/sbb-fonts/`) |
| Scene illustrations: official SBB Mobile illustrations, provided by SBB for the LauzHack 2026 demo (day and night; `easyride-checked-in` has no night version) | `assets/illustrations/*.webp` | `composeResources/drawable/` (task `copyIllustrations`) |
| Touch-timetable tile maps: **Map data © OpenStreetMap contributors (ODbL)**, via OpenFreeMap's z14 vector tiles, rendered in SBB's tile style by `scripts/touch-tiles/touch_tiles.py` (`fetch <cache>`, then `render <cache> assets/touch-tiles`; run by hand) | `assets/touch-tiles/<stationId>.webp` | `composeResources/drawable/touch_<id>.webp` (task `copyIllustrations`), drawn by `screens/plan/TouchTileBackground.kt` |
| Live basemap under the maps: **Map data © OpenMapTiles © OpenStreetMap contributors (ODbL)**, OpenFreeMap's vector tiles (no key), drawn in SBB's map style at runtime; credited on the map. Offline, the baked `assets/map` layers stand in | `https://tiles.openfreemap.org/planet` (TileJSON, then `{z}/{x}/{y}.pbf`) | memory only: `ui/map/TileLayer.kt` (fetch, LRU, parent fallback), `ui/map/VectorTiles.kt` (decode, style) |
| SBB icons (Apache-2.0) | `assets/icons/*.svg` | generated `IconData.kt` (task `genSbbSources`), drawn by our SVG renderer |

## Contract for screen authors

**Add a screen.** One file in `screens/<area>/`, with a destination and the composable:

```kotlin
data class ConnectionDestination(val id: String) : Destination {
    @Composable override fun Content() = ConnectionScreen(id)
}

@Composable
fun ConnectionScreen(id: String) {
    SbbScreen(title = stringResource(Res.string.title_connection), showBack = true) {
        ScreenColumn {               // scrolls; the first card overlaps the red band; clears the tab bar
            SbbCard { ... }
        }
    }
}
```

Tab roots are in `screens/Roots.kt` (`rootDestination(tab)`); replace a stub's body in place.

**Navigate** with `val nav = LocalNavigator.current`:

- `nav.push(dest)`: slide in from the right (265 ms, cubic-bezier(.42,0,.58,1)), the toolbar stays put and its title
  changes at once; `nav.back()` (also system back and the header's arrow): the mirror image.
- `nav.replace(dest)`: no animation. `nav.popToRoot()`. `nav.selectTab(tab)` (re-tapping a tab pops to its root).
- `nav.open(tab, dest1, dest2)`: jump to a tab with a given stack (notifications); `nav.open(DeepLinks.parse(uri)!!)`.
- Each tab keeps its stack; `rememberSaveable` state (scroll, segment) survives tab switches and pushes.
- Tab bar indicators: `TabIndicators.badge(Tab.Tickets, true)`, `TabIndicators.switchOn(Tab.EasyRide, true)`.

**Deep links** (`nav/DeepLinks.kt`): `railstatus://checkin/<trainId>?car=N` -> EasyRide tab + `CheckInLinkDestination`;
`railstatus://incident/<trainId>` -> EasyRide tab + `IncidentDestination`. The web build reads the same routes from the
URL hash (`#/checkin/<id>?car=N`, `#/incident/<id>`).

**Theme.** Wrap nothing yourself: `App()` provides it. Read `SbbTheme.colors` (the colour tokens: `bg`, `card`,
`text`, `text2`, `line`, `red`, `sheet`, `scrim`, `pressed`, ...) and `SbbTheme.type` (`title`, `body`, `bodyBold`,
`small`, `section`, `meta`, `caption`, `big`, ...; line heights as measured on SBB Mobile). Sizes: `SbbDimens`
(in dp, measured on the reference phone). Dark/light follows the system; `AppAppearance.pref` overrides it.
Text: `SbbText(...)` (no Material: we draw everything ourselves to match SBB).

**Components** (`ui/components`, `ui/chrome`):
`SbbScreen`, `Header` (title, back, header content), `Segmented` + `SegmentedPage` (page slide), `ScreenColumn`,
`Modifier.sbbRedBand()`, `SbbCard`, `ListCard` + `ListRow`, `SectionHeader`, `CountBadge`, `NoteCard`, `Hairline`,
`PrimaryButton`, `CtaDock`, `PillButton`, `RoundButton` (Plain/Small/Action/SheetClose/Outline), `SbbIcon(name)`
(any name in `assets/icons`), `Landscape(Scene.Trips)`, `SbbSheet` (modal; shown while composed),
`SbbLoader`, `Modifier.sbbClickable` (SBB's pressed overlay, no ripple), `SbbSignet`.

**Strings**: add to the right `composeResources/values/strings*.xml` file and its `-de`, `-fr`, `-it` twins; use
`stringResource(Res.string.x)` (`railstatus.mobile.resources.Res`).

**The support chat** (spec P4/P5, `screens/easyride/ChatSheet.kt`) is a sheet, not a screen. Open it from anywhere
(the incident page's "Ask a question" row, the EasyRide card):

```kotlin
AskQuestionButton()                        // "Ask a question" (outlined, centred); opens the sheet; shows only while the chat is open
var chat by rememberSaveable { mutableStateOf(false) }
if (chat) ChatSheet(onDismiss = { chat = false })   // or your own button + the sheet
val a = rememberChatAvailability()         // a.open, a.resolved, a.closesAt (the grace window after "Resolved")
ChatEntry()                                // the EasyRide card that opens it
```

Keep `ChatSheet` composed until the passenger dismisses it: it shows its own closed state when the chat closes
(15 min after "Resolved", or on a 403), and the conversation stays readable. `chatSheetOpen` is true while one is up.

**Platform code**: only where a platform truly differs (`expect`/`actual`): `platformServices()` (HTTP client, notifier,
beacon scanner, storage, passenger config; see `AppGraph.kt`), `noFontPadding()` and `DarkStatusBarIcons()`. Android's
foreground ride service, notifications, Bluetooth scan and demo switches are in `androidMain/.../platform/`.
