SCREENPLAY: JETBRAINS PITCH (ABOUT 4 MINUTES)
=============================================

A live demo on four Compose Multiplatform screens, with no slides. It answers the brief's judging points (challenges/jetbrains-kmp.md):
- two or more platforms;
- a native-feeling UX;
- what's shared in commonMain, plus the backend, localization and shared AI;
- innovation;
- the agentic process;
- the presentation.

The setup details and fallbacks are in jetbrains-demo-notes.md and jetbrains-live.md. This file is the run of the show, line by line.

What changed since those notes: the operator now sends the beats with Send beat N in the dashboard's Live demo bar (c119bed), not with Enter in a terminal. The publish dialog shows one line, "Drafted by the Koog agent from N internal messages", so speak the tools rather than point at them.

SCENE 3: THE KOOG AGENT (1:00 – 1:30)
-------------------------------------

OPERATOR: Send beat 2. Then, in the desktop dashboard: Publish a status update. The draft fills in, preselected "from the ticker (AI)".

So the AI can only draft from facts our code computes. A human reads it and publishes."

SCENE 9: WHAT'S SHARED (2:40 – 3:15)
------------------------------------

PRESENTER:
    "We measured it. Counting the shared module it compiles in, the passenger app is 94 percent common code: about 16,600 lines in commonMain, against 870 for Android and under 200 for the web. The dashboard is 98.5 percent common.
    What's shared is the logic that matters: the model, train matching, the update templates, nextMove(), and the chat's rules engine. We ported that engine from TypeScript and proved it against 2,940 golden answers from the old one.
    Only what needs the OS stays per platform: Bluetooth check-in, the foreground service and notifications on Android, browser notifications on the web. That's three expect functions. And the same tests run unchanged on the JVM and as wasm in headless Chrome: 122 runs, zero failures."

SCENE 10: THE DETERMINISTIC CORE (3:15 – 3:30)
----------------------------------------------

PRESENTER:
    "The card a passenger sees is never model output. nextMove() is plain arithmetic on SBB's published facts and the real journey planner. The Koog agent can read it, so the draft never contradicts the card, but a human publishes every word."

SCENE 11: FOUR PEOPLE, FOUR AGENTS (3:30 – 3:55)
------------------------------------------------

PRESENTER:
    "Four of us, each with a Claude Code agent, on one repo at the same time. They coordinated on a GitHub issue as a message board: 304 posts. Every module has an owner. An agent posts a CLAIM before it touches files, the owners ACK, and it posts DONE when it's pushed. One agent is the lead and decides. 180 of our 246 commits carry the Claude co-author line.
    A real thread from tonight: one agent found the chat contradicted the next-move card, fixed it on a branch with tests, the owner's agent reviewed it, the lead approved: six minutes.
    To be clear: we used Claude Code in the terminal, not JetBrains Air."

DON'T CLAIM
-----------

- That the Koog agent runs in the browser. Its wasm target only compiles.
- iOS. "One more target and three actual functions; no Xcode on our laptops."
- That nextMove() runs on the phone. The server computes it; the chat engine does run on the phone offline.
- That the Bluetooth beacon on stage is real. It's simulated; the scanning code is real.

IF SOMETHING BREAKS
-------------------

The fallbacks are in jetbrains-demo-notes.md. In short:
- If Koog fails, the dialog falls back to the single-call draft; speak the Koog point.
- If a screen is dead, point at its twin.
- If the demo is dead, BACKUP plays the recording.
